# 明日方舟攻略模块

根据玩家提供的干员截图建立持有名单，再结合所选关卡、关卡资料和公开攻略来源，生成适配该玩家阵容的攻略报告。

## 目标流程

1. **导入干员截图**：原图按账号快照和日期归档，不覆盖、不修改。
2. **识别并核对**：逐张识别卡片人物和名称，以 PRTS 干员数据、名称和头像交叉匹配；对低置信度、未匹配项明确标记，确认后再更新持有名单。
3. **选择关卡**：支持输入关卡编号或名称；后续可接入关卡列表、敌人和机制数据。
4. **搜索攻略来源**：围绕关卡检索公开资料及 Bilibili 等平台的视频攻略，记录标题、作者、链接、发布时间和可验证的要点。遵守来源站点的访问规则，不下载或转载视频内容。
5. **按阵容评估**：比较来源攻略的阵容与玩家持有名单，优先考虑可用干员覆盖、关卡机制适配、练度要求和攻略信息完整度；无法确认的信息应标为假设，不能伪装成确定结论。
6. **生成报告**：输出推荐方案、替代干员、关键操作/部署顺序、来源链接、生成日期和匹配说明。报告应说明推荐依据，而非只给无来源的“最佳”结论。

## 目录约定

```text
guide/
├── README.md
├── data/                          # 可复用或确认后的数据
│   ├── operators/
│   │   └── owned-operators.md     # 当前确认的持有干员清单
│   └── screenshots/
│       └── YYYY-MM-DD/
│           ├── roster/            # 干员列表截图
│           └── squads/            # 编队等截图
├── research/                      # 按关卡和检索批次保存的来源证据
│   └── <stage-id>/<run-id>/
│       └── sources.json           # 来源 URL、标题、日期及提取要点
└── output/                        # 面向用户的生成结果
    └── <stage-id>/
        └── YYYY-MM-DD.md
```

原始输入、确认后的数据、检索证据和最终报告分开保存。`research/` 用于追溯报告依据；若后续不需要离线复查，可只保留报告中的来源链接。

## 建议的实现顺序

1. 将干员识别拆成“候选识别 → 名称/头像匹配 → 人工确认 → 写入名单”，保留等级、精英化、置信度和未识别项。
2. 关卡对象已由 `prts-crawler stages` 产出（`data/stages.json`），下一步是按代号/名称检索关卡并接入敌人属性。
3. 接入可用且允许访问的搜索来源；保留原始 URL 和检索时间，限制请求频率，并在来源不可用时显式报告。
4. 实现可解释的攻略排序：阵容可用性优先，其次是机制覆盖、操作复杂度、来源质量和信息新鲜度。
5. 输出带引用的 Markdown 报告；每条关键建议应能追溯到关卡数据或攻略来源。

避免把“视频搜索结果”直接等同于可靠攻略：标题、投稿日期和简介只能提供有限证据；无法读取或验证视频内容时，应明确说明限制。
